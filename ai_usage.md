# 2. Nature of AI Assistance

## 2.1 Architecture and Planning

AI was used during the planning stage to help organize project requirements and discuss possible architecture choices.

This included discussion around:

* Frontend/backend separation
* REST API organization
* Database entity relationships
* Role-based access control
* Request workflow structure
* Testing strategy
* Implementation sequencing

The final architecture and business decisions were made by the developer.

Examples of decisions made by the developer include:

* Treating each physical asset as an individual database record.
* Defining Admin, IT Staff, and Employee responsibilities.
* Defining the allowed request and asset state transitions.
* Deciding that a waitlist was unnecessary for the required scope.
* Limiting database transactions and row locking to concurrency-sensitive operations.
* Deferring optional features until the mandatory requirements were complete.

## 2.2 Boilerplate and Project Setup

AI was used more extensively for repetitive setup work where the implementation followed already-decided conventions.

Examples include:

* Initial project scaffolding
* TypeScript configuration
* Express setup
* TypeORM configuration
* Common API/error-handling structures
* Basic route/controller structure
* Repetitive frontend component patterns
* React routing and protected-route boilerplate
* API client setup
* Common form and UI patterns
* Test configuration and repetitive test scaffolding

These were primarily productivity-oriented uses. The developer reviewed the generated structures and adapted them to the project.

## 2.3 Backend Development

AI assistance in the backend was intentionally limited for domain logic.

AI was used for:

* Repetitive controller/route boilerplate
* Basic validation structure
* Common middleware patterns
* Configuration/setup
* Error-handling patterns
* Repository/query scaffolding
* Debugging suggestions
* Test-case generation

The core business logic was developed and reviewed by the developer, including:

* Asset availability rules
* Request eligibility
* Request state transitions
* Approval/reservation behavior
* Allocation rules
* Return behavior
* Damaged-return handling
* Maintenance coupling
* Ownership restrictions
* Concurrency-sensitive operations
* Role-specific permissions

AI suggestions were treated as implementation assistance rather than as the source of the business rules.

## 2.4 Frontend Development

AI assistance was used mainly for repetitive UI implementation and integration work, including:

* React project setup
* Reusable UI component patterns
* Protected routing boilerplate
* API service structure
* Form scaffolding
* Loading/error/empty-state patterns
* Repetitive list/table structures
* Basic dashboard layout
* Frontend test scaffolding

The developer determined the required screens, user flows, role-specific behavior, and final UI behavior and reviewed the generated implementation.

## 2.5 Testing and Test-Case Generation

A significant use of AI was **generating test cases for functionality that had already been implemented by the developer**.

AI was used to suggest:

* Happy-path test cases
* Validation cases
* RBAC cases
* Boundary conditions
* Invalid state-transition cases
* API error cases
* Frontend component cases
* Edge cases that could otherwise be missed

The test suggestions were reviewed and adapted to match the actual implementation.

The purpose of AI in this area was primarily to improve test coverage and identify additional cases, rather than to design the application logic itself.

## 2.6 Debugging and Review

AI was occasionally used after implementation to investigate errors or inconsistencies.

Typical uses included:

* Explaining compiler/test failures
* Suggesting possible causes of failing tests
* Reviewing API behavior
* Identifying inconsistencies between frontend and backend
* Suggesting small refactorings
* Reviewing validation and error handling
* Checking implementation against project requirements

The developer performed the actual verification through tests, type checking, linting, builds, API testing, and manual browser testing.
